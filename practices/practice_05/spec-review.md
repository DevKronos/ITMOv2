# Согласование до реализации второй фичи

| Аспект | Исходное состояние | Решение |
|---|---|---|
| Область | UI и логика описывают текущий город | Совпадает со счётчиком unread; вся история видима |
| Вход | UI не определяет поля, логика читает город при исполнении | Форма передаёт expected_city — город показанной страницы |
| Смена города | В исходных документах не определена | Сравнение нормализованного expected_city с preferences внутри BEGIN IMMEDIATE; устаревшая форма не меняет новый город |
| Выход | Число изменений и redirect совпадают, текст не задан | 303, message «Отмечено прочитанными: N» |
| Ошибки | «русское сообщение», ValueError без HTTP mapping | Доменная ошибка → 303 с message; нет обязательного поля → 422; чужой Origin → 403 |
| Пустое состояние | disabled и 0 согласованы | POST при нуле допустим и возвращает 0; пустой город — ошибка |
| Типы | Уведомление уже содержит city_key/is_read | Новых структур БД нет; storage возвращает int>=0 |
| Совместимость | Каталог не связан с уведомлениями | При поиске отметка касается всего текущего города; после POST редирект сбрасывает поиск как существующие POST |

Обнаружена реальная недостающая гарантия: между показом формы и POST город
может измениться в другой вкладке. Клиентский hidden field не является источником
города, только предусловием. Наивный read_state перед UPDATE оставляет гонку,
поэтому проверка города и UPDATE должны быть в одной блокирующей транзакции.
Принято без изменения архитектуры; нормализованные алиасы не считаются сменой города.

Все FR-001…005 сопоставлены со сценарием и задачей; открытых противоречий нет.
Документы обновлены и снимки сохранены до реализации соответствующего кода.
