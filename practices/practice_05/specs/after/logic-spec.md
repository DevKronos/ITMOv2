# Логика: массовое прочтение — согласованная версия 1.0
- storage.mark_city_read(expected_city: str) -> int>=0. Вход: непустая строка до
100 символов до нормализации; 
- сравнение города существующей normalize_city.
Данные: preferences.city:str, notifications.city_key:str, is_read:0|1, id:int.
В BEGIN IMMEDIATE прочитать city, проверить его непустоту и совпадение с expected_city,
обновить только is_read=0 текущего city_key, вернуть rowcount. Проверка и запись
одной транзакцией. Повтор/нет записей →0; 
- алиасы города равноправны.
ValueError при пустом/длинном expected_city или пустом профиле:
«Сохраните город перед отметкой уведомлений»; 
- при устаревшем городе:
«Город изменился. Обновите страницу и повторите действие». Любая ошибка откатывает запись.
HTTP вызывает storage, перехватывает ValueError, возвращает существующий back(message)
с 303; 
- обязательное поле FastAPI Form; 
- same-origin middleware действует как прежде.
Нет миграции, удаления, смены города/подписок/promotions, новых уведомлений или сети.
Критерии: точное число только новых строк, изоляция городов, повтор 0, rollback ошибок,
сохранение результата при следующем открытии соединения.
Полный контракт: contracts/read-city.md; FR-001…005 в spec.md.

Уточнение 1.1: пустая строка HTTP Form отклоняется FastAPI (422) до storage;
пробельная строка отклоняется storage с ValueError и redirect 303.
