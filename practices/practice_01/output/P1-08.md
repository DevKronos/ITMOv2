 ## Контекст
 
- 
+Сервис AI‑reviewer PR принимает `POST /api/reviews` с JSON `{"diff": "<строка diff>"}` и анализирует только переданный diff. Целевой результат — структурированный JSON с полями: `summary`, `risks` (массив ≤ 3 объектов `{file, line, evidence, risk}`) и `checks`. Ограничения: длина diff ≤ 20 000 символов (при превышении — 413), таймаут внешнего LLM 10 секунд с контролируемым ответом при ошибке, логируются только `request_id`, длительность и статус. Текущее AS IS: эндпоинт обращается к `payload["diff"]` без валидации, сервис возвращает `{"comment": "..."}`, отсутствуют лимит размера и обработка таймаута. Неизвестно: точный формат контролируемых 4xx-ответов и ответов при таймауте.
@@
 ## Решение
 
- 
+Принять целевой контракт и минимальные изменения процесса:
+
+1. Валидация входа: проверять наличие поля `diff` и тип `string`. При отсутствии/неверном типе возвращать контролируемую 4xx-ошибку (точный формат будет согласован отдельно).
+2. Ограничение размера: отклонять запросы с `diff` длиной > 20 000 символов с HTTP 413.
+3. Вызов LLM: выполнять `llm.generate` с таймаутом 10 секунд; при таймауте/ошибке — возвращать контролируемый ответ, без ожидания > 10 секунд (формат будет согласован).
+4. Постобработка: преобразовывать ответ модели в структурированный результат `summary`, `risks` (≤3, `{file, line, evidence, risk}`), `checks`.
+5. Логирование: записывать только `request_id`, длительность и статус; не логировать содержимое diff и ответ модели.
+
+Решение действует в рамках первого сценария, работает только с переданным diff и не выполняет approve/merge или изменения кода.
