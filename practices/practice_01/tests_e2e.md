# E2E-проверки

Файл ведёт OpenCode. Обсудите с агентом содержание и проверьте предложенный diff. Все дополнения и исправления поручайте агенту в чате.

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный | Валидный JSON с полем `diff` типа string; длина `diff` ≤ 20 000 символов; допустимые источники — только переданный diff | Отправить `POST /api/reviews` с указанным JSON | HTTP 200 OK; тело содержит `summary: string`, `risks: array (≤3) of {file, line, evidence, risk}`, `checks: array of string`; логи содержат `request_id`, длительность и статус; содержимое diff и ответа модели не логируется | `product_management.md` (позитивный сценарий), `adr.md` (Решение п.4 и п.5), `analysis.md` (TO BE п.5–6) |
| Негативный | Валидный JSON с полем `diff`; внешний LLM отвечает > 10 секунд | Отправить `POST /api/reviews`; симулировать таймаут LLM | Возвращается контролируемый ответ об ошибке; время ответа ≤ 10 секунд; без 5xx | `product_management.md` (таймаут 10с → контролируемый ответ), `adr.md` (Решение п.3), `analysis.md` (TO BE п.4) |
| Граничный | JSON с полем `diff` длиной > 20 000 символов | Отправить `POST /api/reviews` с `diff` длиной > 20 000 | HTTP 413 Payload Too Large; запрос отклонён на уровне проверки размера | `product_management.md` (413 при >20 000), `adr.md` (Решение п.2 и схема), `analysis.md` (TO BE п.3) |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): будет добавлена после записи задачи про e2e‑проверки.
- Что проверил студент и какие исправления поручил агенту: утвердил три E2E‑сценария по зафиксированным артефактам (200 OK со структурой, 413 при >20 000, контролируемый ответ при таймауте ≤10с); поручил оформить предусловия, действия и ожидаемые результаты без добавления новых требований.
