# Feature Specification: Прочитать уведомления текущего города
Создано 25.10.2026. Статус: согласовано, готово к plan/tasks.
## User Scenarios & Testing
### User Story 1 — Прочесть текущий город (Priority: P1)
Пользователь одним действием отмечает непрочитанные уведомления своего города.
Ценность: не нужно нажимать каждую карточку, история остаётся доступной.
Независимая проверка: история двух городов, действие меняет только выбранный город.
1. **Given** город и два непрочитанных уведомления, **When** пользователь нажимает
кнопку, **Then** счётчик равен 0, история сохраняется, показано число изменений 2.
2. **Given** нет непрочитанных, **When** страница открыта, **Then** кнопка недоступна.
3. **Given** город изменён после открытия страницы, **When** отправлена старая форма,
**Then** видимо сообщение об изменении города и ни одно уведомление не меняется.
### Edge Cases
Пустой город, пустая история, повторное действие, разные города и алиасы города.
## Requirements
### Functional Requirements
- FR-001: Действие доступно при выбранном городе и наличии непрочитанных в нём.
- FR-002: Меняются только непрочитанные уведомления текущего города; история сохраняется.
- FR-003: Повторное действие сообщает 0 изменений.
- FR-004: Устаревшая форма при смене города отклоняется без изменений.
- FR-004a: Ошибочные запросы не изменяют данные; используется существующая защита Origin.
- FR-005: Поиск каталога и индивидуальное прочтение сохраняют прежнее поведение.
### Key Entities
Профиль с городом; уведомление с городом и отметкой прочтения.
## Success Criteria
- SC-001: Одно действие отмечает все уведомления нужного города; число изменений точно.
- SC-002: Ни одна запись другого города не меняется и ни одна запись истории не удаляется.
- SC-003: При повторе число изменений 0, число записей остаётся прежним.
## Assumptions
Один локальный профиль, существующие нормализация города и механизм форм.
Автоматические HTTP и SQL проверки обязательны.
