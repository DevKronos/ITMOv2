# Акции рядом — установка и запуск

Локальный сервис Python/FastAPI/SQLite/Jinja2: город, подписки, реальные акции
и уведомления внутри приложения. Подключён только ROSTIC’S. В каталоге есть
другие сети, но их сборщики и внешняя доставка сообщений не подключены.

## Установка

Python 3.11+, Linux/WSL. Все команды выполняйте из корня приложения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m pip check
.venv/bin/python scripts/check.py
```

Если недоступен ensurepip, сначала установите системный пакет python3-venv.
Рабочую .venv не удаляйте. Активация не нужна: запускайте локальный Python явным
путём, даже если в частично созданной .venv отсутствует activate.
requirements.txt содержит прямые зависимости, requirements-dev.txt — зависимости
разработки, requirements-lock.txt — полный проверенный набор, включая MCP SDK
2.3.0. Для тестов устанавливайте lock-файл. Глобальные Python-пакеты не нужны.

## Приложение

Без обращений к источнику:

```bash
.venv/bin/python -m app.cli import-snapshots
APP_BACKGROUND=0 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000, сохраните город и подпишитесь на Rostic’s.
«Проверить сохранённые акции» создаёт подходящие уведомления без обновления
источника. «Обновить источник» обращается к сети даже при APP_BACKGROUND=0.
Snapshots — реальные исторические страницы от 7 октября 2026 года, а не новый
онлайн-сбор. Завершившиеся акции не дают уведомлений; даты не корректируются
ради демонстрации. Город, подписки, история и отметки прочтения сохраняются.

Эти команды используют рабочую базу. Для проверок задавайте одну новую временную
APP_DB_PATH обеим командам, например:

```bash
demo_dir=$(mktemp -d)
APP_DB_PATH="$demo_dir/promos.db" .venv/bin/python -m app.cli import-snapshots
APP_DB_PATH="$demo_dir/promos.db" APP_BACKGROUND=0 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Обычный онлайн-запуск (кнопка обновления и фон используют сайт):

```bash
env -u APP_SNAPSHOT_DIR APP_BACKGROUND=1 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

CLI: `.venv/bin/python -m app.cli --help`; команды import-snapshots, sync,
notify, preview. preview не создаёт уведомления, но обычный CLI может
инициализировать базу; строгое чтение реализовано отдельно для MCP.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| APP_DB_PATH | data/promos.db | SQLite-база |
| APP_BACKGROUND | 1 | 0 отключает фон |
| APP_SYNC_INTERVAL | 1800 | Интервал фона в секундах, минимум 60 |
| APP_SNAPSHOT_DIR | не задана | Источник snapshots вместо сети для sync/фона |

Фон работает только пока запущен сервер, первый сбор — после интервала.
Используйте один worker. Сервис рассчитан на один локальный профиль, без
регистрации; не публикуйте его как многопользовательское приложение.

## Правила сбора и уведомлений

Каталог https://rostics.ru/promo и страницы собираются последовательно,
максимум за 3 попытки на страницу. Тайм-аут сокета — 20 с на попытку,
паузы — 0,5 и 1 с. Повторяются временные сетевые сбои и HTTP
408/500/502/503/504; 403/404/429, ошибки TLS, постоянные и неклассифицированные
ошибки и ошибки HTML не повторяются. Ограничение ответа — 5 000 000 байт,
перенаправления проверяются по домену. Параллельный sync блокируется.

Частичный сбор сохраняет успехи и прежние записи. Только полный подтверждённый
каталог позволяет пометить отсутствующие акции. Неизвестные сроки/территория
не разрешают уведомление; отсутствие городов не означает действие по всей РФ.
Сроки и дни недели проверяются в Europe/Moscow, последний день включён.
Дедупликация: сеть + ID акции + нормализованный город + версия содержимого;
одно лишь новое время получения не создаёт уведомление. История хранит снимок
условий, а не гарантию товара или персонального допуска к акции.

При FlClash проверяйте окружение терминала сервера: urllib использует
getproxies(), HTTPS_PROXY/HTTP_PROXY/NO_PROXY; ALL_PROXY не заменяет HTTPS_PROXY.
Не выводите адреса с учётными данными. После изменения окружения перезапустите
uvicorn. Успешный запрос не доказывает исчезновение временных сбоев; VPN как
причина прежних тайм-аутов не доказан. Защита сайта не обходится, TLS не отключается.

## MCP для OpenCode

Один tool preview_notifications возвращает city, subscriptions, checked_at,
notifications (кандидаты), excluded (network/source_id/первая reason) и explanation.
Он использует service.preview_notifications без сети, импорта, создания
уведомлений, изменения настроек или отправки сообщений. Вход: объект с
необязательным now — строкой ISO 8601 с часовым поясом; другие поля запрещены.
Без now используется текущее время одного вызова. Ошибки возвращают isError=true,
сервер продолжает работать; успешные данные есть в structuredContent и text JSON.
Путь базы задаётся APP_DB_PATH при запуске, не аргументом tool.

Для строгого отсутствия записей SQLite используется mode=ro&immutable=1 и
query_only без bootstrap. Требуется **неактивная база без конкурирующих писателей**.
При наличии WAL инструмент отказывает, поскольку immutable игнорирует WAL.
Не удаляйте WAL вручную; штатно закройте писателей или подготовьте новую базу.
Чтение живой WAL-базы работающего веб-приложения не поддерживается. Отсутствующая
база/схема даёт ошибку без создания файла/таблиц. Без APP_DB_PATH при прямом запуске
действует обычный путь data/promos.db; для демонстрации всегда задавайте отдельный.

Подготовка — отдельная операция; скрипт отказывается менять существующую базу
и data/promos.db:

```bash
APP_DB_PATH=.opencode/demo/promos.db .venv/bin/python scripts/prepare_mcp_demo.py
APP_DB_PATH=.opencode/demo/promos.db APP_BACKGROUND=0 .venv/bin/python scripts/mcp_server.py
```

Если demo-база уже существует, не сбрасывайте её: используйте новый путь и тот же
путь в opencode.json. Подготовка импортирует 13 snapshots, Санкт-Петербург,
подписку rostics, без уведомлений. На 2026-10-07T12:00:00+03:00 ожидаются
7 кандидатов и 6 исключений. Без фиксированного now исторические акции могут
оказаться завершёнными.

Вторая команда запускает stdio-сервер для MCP-клиента, а не интерактивный CLI.
stdout содержит протокол, диагностика идёт в stderr. Launcher задаёт корень
проекта; из другого каталога указывайте абсолютные пути к Python и launcher.
Относительный APP_DB_PATH разрешается от корня приложения.

opencode.json подключает local server discount_notifier для OpenCode 1.18.35:
локальный Python, отдельная .opencode/demo/promos.db, фон выключен, timeout 15 с.
В OpenCode tool называется discount_notifier_preview_notifications. После
подготовки базы полностью перезапустите OpenCode из корня приложения; вручную
запускать второй stdio-сервер не нужно. Глобальная конфигурация не изменяется.

## Hook и проверки

OpenCode автоматически загружает .opencode/plugins/python-check.js при новом
запуске процесса. Успешные edit/write/apply_patch Python в app/tests/scripts
запускают одну проверку на вызов инструмента. PASS попадает в tool output,
FAIL — в ошибку инструмента с кодом/диагностикой; сохранённая правка не откатывается.
Тайм-аут — 60 с на процесс, вывод ограничен 8000 символами на поток. Markdown,
skill и неизменившиеся файлы пропускаются; shell/внешние/custom tools не покрыты.
Hook использует временную базу и выключенный фон; POSIX-группа процессов проверена
в WSL. Это не сетевая песочница для произвольного будущего кода тестов.

```bash
.venv/bin/python scripts/check.py
node --test .opencode/tests/python-check.test.mjs
```

Python suite проверяет синтаксис, приложение и настоящий MCP stdio с временными
базами без сети. Фон проверяется управляемым сборщиком. Повтор lifecycle TestClient
в одном процессе не является перезапуском отдельного uvicorn; процессный smoke
не входит в scripts/check.py. Node 22 используется для тестов hook; его runtime
не требует дополнительных npm-пакетов. Существующие локальные служебные зависимости
OpenCode при восстановлении можно установить через `npm ci --prefix .opencode`.

## Среда OpenCode и сценарии проверки

AGENTS.md задаёт карту проекта, рабочие команды и правила сохранения данных.
Готовый skill помогает установить причину ошибки до исправления; hook возвращает
агенту автоматический результат общей проверки после Python-правки.
Собственный MCP даёт объяснимый предпросмотр через ту же бизнес-логику, без SQL,
обновления источника и изменения уведомлений. Среда подготовлена для OpenCode
1.18.35; конфигурация не требует изменения глобальных настроек.

### Готовый skill

systematic-debugging из [obra/superpowers](https://github.com/obra/superpowers)
задаёт четыре фазы: свидетельства, сравнение, проверку гипотезы и минимальное
исправление с повторной проверкой. SKILL.md содержит рабочую инструкцию,
а связанные материалы уточняют трассировку причины, защиту и ожидание условий.
Локальная адаптация заменяет ссылки на два отсутствующих skills воспроизведением
ошибки и штатной проверкой Python; shell/TypeScript-примеры сохранены как
иллюстрации и не запускаются для этого приложения. Оригинал, лицензия MIT
© 2025 Jesse Vincent и описание изменений сохранены в
[каталоге skill](.opencode/skills/systematic-debugging/SOURCE.md): версия v6.4.2,
commit 8ca22dba9a94f28898bbce59f2537ff4d87c747d.

Короткий промпт OpenCode:

```text
Прочитай AGENTS.md и CONFIG.md. Загрузи systematic-debugging штатным skill tool.
Проверь Python/pip, pyvenv.cfg, ensurepip и наличие activate в .venv.
Если activate отсутствует, установи причину и оцени запуск через .venv/bin/python;
рабочую venv не перестраивай. Применяй четыре фазы skill; если проблема устранена,
не придумывай исправление. Не обращайся к источникам, не меняй README, базу и skill.
```

Свидетельство — реальный skill({name:"systematic-debugging"}), полученный текст
и применение фаз; обнаружение в списке или чтение файла не заменяет загрузку.

### Автоматический FAIL/PASS hook

В отдельной копии проекта с зависимостями и временной базой создайте через
edit/write/apply_patch корректный app/hook_demo.py → автоматический PASS.
Внесите `def broken(` → FAIL с SyntaxError, проверьте сохранение правки;
исправьте → PASS. Один patch двух Python-файлов должен дать одну проверку,
Markdown-правка — ни одной. Не ломайте рабочий код или .venv ради демонстрации.
Нужен журнал вызова редактора с автоматически полученным результатом, а не
отдельная ручная команда. После FAIL агент читает причину и исправляет её.

Plugin .opencode/plugins/python-check.js использует helper
.opencode/lib/python-check.mjs и tool.execute.before/after: before сохраняет
хеши, after обрабатывает metadata успешного редактора. Провал редактирования
не запускает after; пакетный apply_patch даёт один запуск. Watcher отсутствует,
поэтому файлы самой проверки не инициируют рекурсию. Для загрузки plugin нужен
полный перезапуск OpenCode, а не новая беседа в прежнем сервере.

### MCP: корректный и ошибочный вызовы

После подготовки отдельной неактивной базы и перезапуска OpenCode:

```text
Прочитай AGENTS.md. Вызови именно discount_notifier_preview_notifications с
{"now":"2026-10-07T12:00:00+03:00"}, без shell/CLI/Python-замены.
Покажи город, подписки, checked_at, число кандидатов и причины исключения.
Повтори MCP-вызов и сравни ответы. Поясни: это сохранённые исторические данные,
без онлайн-сбора, записи уведомлений и отправки сообщений.
```

Ещё не проверенный агентный сценарий ошибки:

```text
Намеренно вызови MCP discount_notifier_preview_notifications с
{"now":"2026-10-07T12:00:00"}, не исправляя часовой пояс заранее.
Покажи фактический isError и сообщение. Затем вызови тот же tool с
{"now":"2026-10-07T12:00:00+03:00"} и покажи восстановление.
Не заменяй MCP shell/Python и не меняй базу.
```

Свидетельство — журнал OpenCode с именем tool, аргументами, ответом и реакцией
агента. Наличие подключения или тест SDK-клиентом не доказывает агентный вызов.

## Подтверждения и ограничения проверок

Codex проверил приложение, MCP настоящим stdio-клиентом (initialize,
tools/list/tools/call), обработку ошибочных аргументов и восстановление,
неизменность данных/схемы базы и управляемые сценарии hook. На исторических
snapshots при указанном фиксированном now — 7 кандидатов и 6 исключений.
Это отдельные проверки кода/протокола, а не демонстрация агента OpenCode.
По сведениям пользователя OpenCode выполнил успешный MCP-вызов; пользователь
также предоставил вывод загрузки systematic-debugging и автоматических
FAIL/PASS hook. Codex эти агентные действия независимо не повторял.
Ошибочный агентный MCP-вызов не проверялся. reflection.md студент пишет сам.
Успешные полные тесты выполнялись в WSL вне ограниченного sandbox;
Windows без WSL не проверен. При этой уборке сетевых запросов не выполняли.

## Состав для GitHub

Сохраняйте приложение, тесты, scripts, snapshots ROSTIC’S, requirements/lock,
README.md, AGENTS.md, CONFIG.md, opencode.json и скрытые .opencode/plugins,
.opencode/lib, .opencode/tests, .opencode/skills с оригиналом и лицензией.
Локальные .opencode/package.json/package-lock.json доступны для добавления:
они позволяют восстановить служебные зависимости через npm ci.
.gitignore исключает .venv, node_modules, кэши, SQLite/WAL/SHM, логи и секреты;
базы остаются локально. Правила игнорирования не удаляют уже отслеживаемые файлы.
