# catalog-search Specification
## Purpose
Помочь пользователю находить сохранённые ресторанные предложения по тексту заголовка и полных условий без обращения к сети и изменения данных.
## ADDED Requirements
### Requirement: Локальный поиск
Система SHALL искать одну подстроку в title или conditions, используя casefold,
замену ё на е и свёртку пробельных последовательностей в один пробел в обоих текстах.
Результат сохраняет исходный порядок. Пустой нормализованный q возвращает весь каталог.
#### Scenario: Поиск по полным условиям
- **WHEN** GET /?q=СКИДКА содержит текст из условий акции
- **THEN** HTML показывает совпадающие карточки и их количество, q сохранён в поле
#### Scenario: Пробелы и ё
- **WHEN** q содержит смешанный регистр, ё или повторные пробелы
- **THEN** сравнение использует одинаковую нормализацию для запроса и полей
### Requirement: Состояния интерфейса и ограничения
Система SHALL предоставлять GET форму q с maxlength=100 и ссылку сброса /#catalog.
После нормализации допускается не более 100 символов; ошибочный запрос показывает
русскую ошибку role=alert, HTTP 200 и полный каталог. Исходное значение экранируется.
#### Scenario: Нет совпадений
- **WHEN** непустой допустимый запрос не найден в непустом каталоге
- **THEN** показано «По вашему запросу акции не найдены» и счётчик 0
#### Scenario: Превышение длины
- **WHEN** нормализованный q имеет 101 символ
- **THEN** показана ошибка «Поисковый запрос — до 100 символов» и полный каталог
#### Scenario: Пустой каталог
- **WHEN** данных нет даже без поиска
- **THEN** сохранена существующая подсказка импорта
### Requirement: Сохранение поведения
Система SHALL оставлять API state, уведомления, город, подписки, сроки,
территорию, импорт и порядок каталога без q без изменений. Поиск не обращается к сети.
#### Scenario: Изоляция поиска
- **WHEN** пользователь выполняет поиск и сброс
- **THEN** содержимое /api/state остаётся одинаковым и все карточки снова доступны
