Проект: **ИИ-помощник студента по заданиям и дедлайнам**. Он читает задания, составляет план работы и по подтверждению студента отправляет выбранный файл в учебную систему.

| Составляющая | Содержание |
|---|---|
| **1\. Компонент сервиса с AI** | Чат с ИИ-помощником. ИИ анализирует запрос студента, получает через сервер задания и дедлайны, читает приложенные документы и предлагает план. Для отправки работы формирует запрос к серверу. |
| **2\. Активы / данные** | Профиль студента, список курсов, задания, дедлайны, оценки, файлы работ, история переписки и токен доступа к учебной системе. Защищаем конфиденциальность данных, целостность работ и возможность вовремя их сдать. |
| **3\. Угрозы** | **Prompt injection:** инструкция внутри документа заставляет ИИ запросить чужие файлы или отправить лишние данные. **Нарушение доступа:** подмена ID позволяет получить чужую работу или оценку. **Нежелательное действие:** ИИ отправляет черновик без согласия студента. **Утечка:** данные разных студентов смешиваются в контексте или попадают в логи. **Перегрузка:** большие документы и частые запросы делают сервис недоступным. |
| **4\. Меры защиты** | Сервер проверяет владельца каждого задания и файла. ИИ получает только необходимые данные, без токенов доступа. Документы считаются недоверенным содержимым. Доступные ИИ инструменты ограничены; сервер проверяет их аргументы и права независимо от ответа модели. Перед отправкой студент подтверждает конкретный файл и задание. Контексты пользователей изолированы, чувствительные данные скрываются в логах. Размеры документов и частота запросов ограничены. |
| **5\. Проверки** | Вставить в документ вредоносную инструкцию и проверить, что запрещённое действие не выполняется. Подменить ID файла или студента — получить отказ без раскрытия данных. Попытаться отправить работу без подтверждения или заменить файл после подтверждения — получить отказ. Проверить отсутствие чужих данных в переписке и секретов в логах. Превысить лимиты запросов и размера файла — получить контролируемую ошибку. Проверить обычный сценарий: студент видит свои дедлайны и успешно сдаёт подтверждённую работу. |

**Главный принцип модели угроз:** ИИ предлагает действия, а сервер независимо проверяет, разрешены ли они. Даже если модель поддалась вредоносной инструкции, защита должна остановить действие
