## Запрос

Найти в разрешённых источниках подтверждения по: размеру diff, таймауту обращения к LLM, времени ответа API, одновременной нагрузке, требованиям к производительности, логированию и ожидаемым HTTP‑ответам. Сопоставить с текущими формулировками в `rag/test_load.md`, отметить подтверждённые и неподтверждённые утверждения и обновить файл без введения новых численных требований.
## Ответ со ссылками на источники

1. Размер diff → подтверждено:
   - context.md (стр. 41): «Ограничения производительности: diff длиннее 20 000 символов отклоняется с HTTP 413.»
   - adr.md (п.2): «Ограничение размера: … > 20 000 символов … HTTP 413.»
   - Применение: сценарий «Превышение размера diff под нагрузкой» ожидает 413; в валидных запросах указан предел ≤ 20 000.

2. Таймаут LLM → подтверждено:
   - context.md (стр. 42): «Внешний вызов LLM: таймаут 10 секунд; ошибки преобразуются в контролируемый ответ.»
   - problem.md (стр. 22): «100% таймаутов маппятся в контролируемый ответ; клиент не ждёт >10 с.»
   - adr.md (п.3): «выполнять … с таймаутом 10 секунд; при таймауте — контролируемый ответ; без ожидания > 10 секунд».
   - Применение: сценарий «Таймаут LLM под нагрузкой» требует контролируемого ответа и времени ответа ≤ 10 секунд.

3. Время ответа API (SLO для успешных 200) → неподтверждено:
   - В источниках отсутствует общий SLA для времени ответа 200‑ответов; 10 секунд относится к таймауту LLM.
   - Применение: убрано требование «Для каждого запроса время ответа ≤ 10 секунд»; оставлена фиксация распределения латентности без порога.

4. Одновременная нагрузка (конкурентность, RPS) → неподтверждено:
   - Источники не задают численные пределы по concurrency/RPS.
   - Применение: сценарии используют одновременные запросы без численных порогов.

5. Требования к производительности (прочие SLO) → частично подтверждено:
   - Подтверждены только: 413 при >20 000 и таймаут 10 с с контролируемым ответом.
   - Иные SLO (черезput/latency) — отсутствуют и не вводятся.

6. Логирование → подтверждено:
   - context.md (стр. 43): «фиксируются только request_id, длительность и статус; содержимое diff и ответ модели не логируются.»
   - adr.md (п.5): повторяет правило логирования.
   - Применение: сценарий логирования проверяет наличие обязательных полей и отсутствие контента.

7. Ожидаемые HTTP‑ответы → частично подтверждено:
   - adr.md/схема: 200 OK со структурированным телом при успехе; 413 при превышении размера diff; при таймауте — контролируемый ответ (точный код/тело не определены).
   - Применение: проверяется структура 200‑ответа; 413 для большого diff; для таймаута — только факт контролируемой ошибки без кода статуса. Утверждение «отсутствие 5xx» снято как неподтверждённое.
