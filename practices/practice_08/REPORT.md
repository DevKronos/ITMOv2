# Практика 8 — «Акции рядом»

## Сценарий и прототип

Пользователь задаёт город, чтобы сервис учитывал его при подборе уведомлений. Он вводит город и нажимает «Сохранить город»; приложение сохраняет его в SQLite и показывает подтверждение. После сохранения нужно обновить страницу: сервер заново рассчитает территориальные метки и данные уведомлений. Сохранение города само по себе не создаёт уведомления; для этого нужны подписка и проверка акций. Подключён единственный источник — ROSTIC’S, уведомления отображаются в приложении.

[Макет формы и её состояний](prototype/city-flow.svg) — SVG-прототип, созданный на основе существующего интерфейса. Показаны пустая форма, ввод и фокус, сохранение, успех и ошибка. При реализации добавлено явное пояснение о необходимости обновить страницу для пересчёта остальных данных. Сообщение в макете сокращено для читаемости; фактический текст приведён в интерфейсе. При отключённом JavaScript работает прежняя серверная форма.

## Запуск

Из каталога `practices` установите Python 3.11+ и зависимости приложения:

```bash
cd practice_04/discount-notifier
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
```

Для автономной демонстрации используйте **новую** временную базу и исторические сохранённые страницы:

```bash
demo_dir=$(mktemp -d)
export APP_DB_PATH="$demo_dir/promos.db"
export APP_BACKGROUND=0
export APP_SNAPSHOT_DIR=research/snapshots
.venv/bin/python -m app.cli import-snapshots
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Сохранённые страницы являются историческими: срок акций мог истечь, демонстрация не подтверждает доступность онлайн-источника. Команды не затрагивают рабочую базу `data/promos.db`. Для рабочего запуска и подробностей см. [README приложения](../practice_04/discount-notifier/README.md).

## Интерфейс и тесты

Использована библиотека **Bootstrap 5.3.8**: карточка, поле и кнопка формы используют классы `card`, `form-control`, `form-label`, `btn`, `btn-success`. Локальная копия CSS и лицензия находятся в `app/static`, сеть при открытии страницы не требуется. Цвета и общие стили — в `app/static/style.css`: светлый фон, синие элементы управления и коралловые акценты. Палитра макета обновлена вместе с интерфейсом. Видимый фокус, подпись поля, сообщения через `aria-live`, адаптивная сетка и клавиатурная отправка обеспечиваются разметкой и стилями. Защита от повторного запроса использует флаг `pending` и отключает кнопку до получения ответа.

Клиентские тесты используют Vitest, jsdom и Testing Library. Они извлекают форму из настоящего шаблона, запускают её скрипт и подменяют `fetch`: проверяют пустое и некорректное значение, ввод и сохранение с отображением результата, ожидание и повторную отправку, ошибку и повторную попытку. Формат успешного ответа `{"city":"Москва"}` и ошибка `{"detail":"..."}` дополнительно проверены серверным тестом на реальном хранилище.

Для клиентских тестов нужен Node.js 20, 22 или 24+. Из каталога `practices` выполните:

```bash
cd practice_08
npm ci
npm test
```

[Результат клиентских тестов](results/client-tests.txt). Общая серверная проверка из каталога `practices`: `cd practice_04/discount-notifier && .venv/bin/python scripts/check.py` — 62 теста прошли. В песочнице проверка зависала на тестах с сетевыми сокетами; успешный запуск выполнен вне неё. Для проверки качества временно убрали текст ошибки в `city.js`: тест повторной попытки упал, затем код восстановлен и все клиентские тесты снова запущены.

## Использование AI

Codex изучил существующие маршруты и предложил сценарий сохранения города, разработал SVG-макет и форму на Bootstrap, добавил HTTP-маршрут к существующему хранилищу и тесты видимого поведения. Примеры заданий, определявших работу: «создай макет формы города с пустым состоянием, вводом, загрузкой, успехом и ошибкой»; «переиспользуй компоненты Bootstrap и подключи форму к существующей логике»; «проверь ввод, ошибку, задержанный ответ и защиту от повторной отправки». При проверке добавлено пояснение об обновлении страницы для пересчёта каталога и уведомлений; тесты изменены так, чтобы использовать разметку реального шаблона, а не отдельный вымышленный HTML. Эти формулировки описывают ход работы, а не отдельные внешние запросы к другому сервису.

Скриншоты предоставлены пользователем; Codex просмотрел их, но самостоятельно не проверял интерфейс в браузере. SVG-макет — прототип, а не скриншот.

`npm audit` сообщил об уязвимостях тестовой зависимости `@vitest/mocker` (moderate и critical). Попытка `npm audit fix` не устранила предупреждения; получение данных об актуальной версии завершилось сетевой ошибкой. Vitest используется только локально для тестов; не запускайте его сервер или UI в недоверенной сети до обновления и повторной проверки аудита.
